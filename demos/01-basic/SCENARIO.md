# Demo 01 — basic carving from a mixed blob

## Situation

A triage analyst pulls an unknown binary artifact (`evidence.blob`) off a host
they own. It looks like junk in a hex editor, but several real files have been
concatenated and padded into it — a common way to smuggle data inside one
opaque container. We want to recover the embedded files without booting the
source system.

`evidence.blob` was generated by `make_demo.py` (committed alongside it) and
contains, separated by random padding:

1. A small valid **PNG** image (with proper `IEND` footer).
2. A tiny **PDF** document (with `%%EOF` footer).
3. A **ZIP** local-file-header + end-of-central-directory record.
4. A **GZIP** stream header.

## Run it

```sh
# List what's hidden inside (writes nothing). Exit code 1 = findings.
python -m filecarve scan demos/01-basic/evidence.blob

# Machine-readable for pipelines
python -m filecarve scan demos/01-basic/evidence.blob --format json

# Shareable HTML report (the "UI")
python -m filecarve scan demos/01-basic/evidence.blob --format html -r report.html

# Actually recover the files to ./recovered
python -m filecarve carve demos/01-basic/evidence.blob -o recovered

# Only hunt for documents
python -m filecarve scan demos/01-basic/evidence.blob --type pdf --type zip
```

## What to expect

The scan reports at least the PNG, PDF, ZIP and GZIP regions with their byte
offsets, sizes, SHA-256 hashes, severity hints (archives/executables rank
higher for analyst attention), and the method used to find each file's end
(`footer`, `length`, or `bounded`). A `bounded` method with the truncation
flag means no end marker was found and a size cap was applied — review those
manually.
